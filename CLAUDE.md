## Идея в одном абзаце

Защищаем честных клиентов от статуса дроппера. Если клиенту пришли чужие деньги, приложение сразу предупреждает и даёт вернуть их отправителю одной кнопкой. Если мошенник уговаривает переслать деньги дальше («ошибочный перевод»), перевод останавливается. Если пострадавший жалуется, система идёт по цепочке переводов: у похожего на невольного участника замораживает только спорную сумму, остальные счета приостанавливает; пострадавший видит статус жалобы и получает замороженные деньги назад. Невольный участник подаёт апелляцию прямо в приложении, со сроком ответа. Втянутый в схему (обычно студент) может сам сообщить банку «Меня втянули» и получить подтверждение с датой. Сотрудник банка видит цепочку, подсказку «невольный участник или организатор» и принимает решение. Вокруг этого: списки Антифрод-центра, сигнал оператора о звонке, доверенное лицо, предупреждение о вербовке, справка о снятии ограничений, проверка подозрительного сообщения, период охлаждения, «встречный кредит» (деньги свежего кредита уходят новому получателю, кредит можно вернуть одной кнопкой), панель эффективности с показателем «Не пришлось возмещать».

- Работаем по задачам, которые дал пользователь. Новые функции предлагать списком и ждать выбора, не делать без спроса.
- Тексты для клиента: простым языком, на «вы», без канцелярита; всё на русском и казахском.
- Не обещать в текстах юридических последствий, которые не проверены (например, банк НЕ может сам исключить клиента из базы Антифрод-центра).
- Отправлять на GitHub (`git push`) только после того, как пользователь сказал «отправь». Коммитить можно, но сначала показать, что сделано.
- Правки оформления — ровно то, что попросил пользователь, без лишнего. Если не уверен, куда поставить или какой цвет, предложить 2–3 варианта и спросить.

## Оформление (согласовано с пользователем)

- Стиль по образцу приложения bcc.kz: белый фон страниц, белые карточки с тонкой рамкой `#d6eadf`, скругление 16 px, шрифт Roboto Flex (без загрузки из интернета).
- Акцент — фирменный зелёный `#00ab75` (текст на белом — `#00875c`). Серый пользователю не нравится: вместо серых оттенков мягкие зелёные (`#e6f3ed` заливка, `#587366` подписи).
- Верхнее меню на всех четырёх страницах (экран клиента, панель аналитика, эффективность, качество движка) слева после «Чистый счёт»: выбранный пункт залит зелёным с белым текстом, остальные — чёрный текст без рамок. Так же вкладки «Ждут решения / Все / Связанные счета». «Сбросить демо» и «Выйти» — белые с зелёной рамкой.
- Экран клиента — телефон с вкладками «Главная / Переводы / Защита». Слева демо-панель: выбор персонажа и подсказка залиты зелёным с белым текстом, кнопка «Имитировать звонок» красная, примеры сообщений жёлтые. На узком экране демо-панель сворачивается в кнопку.
- Без градиентов, теней-эффектов и эмодзи: проект не должен выглядеть сгенерированным.

## Команды

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload          # http://127.0.0.1:8000/ (клиент), /analyst (код 2026), /analyst/stats, /quality
python -m pytest -q                    # 94 теста, ~30 с; каждый тест на своей копии базы (на Windows 1 пропускается)
python -m app.quality                  # пересчитать app/static/quality.json (10 наборов данных, несколько минут)
```

Первый запуск сервера ~10 с: создаются демо-данные и история за 30 дней (`CA_DEMO_HISTORY=1`).

Переменные окружения: `CA_DB`, `CA_UPLOADS`, `CA_DOC_KEY` / `CA_DOC_KEY_FILE`, `CA_ANALYST_PIN` (по умолчанию 2026), `CA_DEMO_HISTORY` (1/0), `CA_TZ` (Asia/Almaty), `CA_COOLING_MINUTES` (60), `CA_PUBLIC=1` (хостинг: без PIN код случайный), `CA_HTTPS=1` (secure-куки), `PORT`.

## Устройство

- `app/main.py` — весь API (FastAPI). Один запрос = одна транзакция (зависимость `tx()` с замком; в ней же `_settle_due()` проводит переводы, у которых закончился период охлаждения).
- `app/engine.py` — правила перехвата. Каждый признак = баллы + текст причины. Порог 85, если на счёте есть «чужие» деньги; 60 без них (звонок, серый список, опасное сообщение, деньги свежего кредита). Окно 120 ч, для кредита 72 ч (`fresh_loan`). Также `assess_role` (подсказка сотруднику), `recruitment_signal`, `find_forward`.
- `app/messages.py` — распознавание схем в тексте сообщения (правила ru+kk): mistaken, safe_account, investment, job, fake_letter, fake_alert, fake_invoice. Новые схемы ставить после прежних (при равных баллах побеждает прежняя).
- `app/seed.py` — синтетика (300 клиентов, 90 дней) и демо-персонажи 1001–1013. `app/history.py` — смоделированная история случаев за 30 дней (и модель «серого» списка для синтетических дропперов).
- `app/metrics.py` — панель эффективности (в т. ч. `_compensation` — «Не пришлось возмещать», `_loans`) и связанные счета. `app/quality.py` — качество движка.
- `app/i18n.py` — тексты сервера ru/kk (`t(key)`), казахские имена персонажей, причины по коду.
- `app/db.py` — схема SQLite; `SCHEMA_VERSION` (сейчас 10): старая база удаляется и создаётся заново.
- Кредит (таблица `loans`) — не перевод: выдача и возврат (`POST /loans/{id}/repay`) меняют баланс напрямую, в ленте клиента он добавляется через `_loan_feed`.
- Статус клиента: `active` | `limited` (соразмерная блокировка: заморожено `cases.frozen`, переводы только прежним получателям) | `blocked`. Статус всегда пересчитывает `_refresh_status(cid)` по нерешённым блокировкам (`UNRESOLVED`) и их `scope` (`full` | `partial`); напрямую `clients.status` не менять.
- `app/vault.py` — шифрование документов (Fernet). `app/clock.py` — время Казахстана.
- `app/static/index.html` — экран клиента (тексты в объекте `T`, ru/kk; подсказки персонажей `hint_<id>`; вкладки — `showTab()`, сообщения — всплывающий `note()`). `analyst.html`, `stats.html`, `quality.html`. Стили у каждой страницы свои, внутри файла; верхнее меню повторяется во всех четырёх — менять везде одинаково.
- `tests/test_flow.py` — сквозные тесты.

## Как вносить изменения (сложилось за проект)

- Меняешь схему базы → подними `db.SCHEMA_VERSION` и добавь новую таблицу в список очистки в `seed.populate(reset=True)`.
- Деньги двигаются только через `_move`; резерв = переводы со статусом `held` и `pending` (`_held_sum`) плюс замороженное (`_frozen_sum`); доступно = `_available(cid)`. Возврат пострадавшему — `_refund` (не больше замороженного и недополученного, `_returned_sum`). Каждое действие по случаю — `log(...)`.
- Любой новый текст для клиента — в `i18n.MSG` (сервер) или в `T` в `index.html`, сразу на двух языках. Казахский потом вычитывает носитель.
- На каждую функцию и каждую исправленную ошибку — тест в `tests/test_flow.py` (сначала воспроизвести, потом чинить).
- Поменял движок → `python -m app.quality` и обнови цифры в README (сейчас: ловит 88%, ложных остановок 0,20%).
- После правок экранов — проверка в браузере (Playwright, ширина телефона 400 px, без горизонтальной прокрутки, без ошибок на странице).
- Обнови `README.md` (сценарий показа, «Как защищены деньги и данные») и `docs/HISTORY.md`.
- Коммиты на русском, одной строкой суть + список изменений.

## Подводные камни

- Индекс по `transfers(status)` ломает план запросов и вдвое замедляет движок; для отложенных переводов — частичный индекс `ix_tr_pending`.
- Имена синтетических клиентов («Данияр О.», «Руслан А.») совпадают с персонажами: в тестах и браузерных проверках искать по «Данияр (продаёт», «Руслан (счёту».
- Даты хранятся как наивное местное время Алматы (ISO-строки); сравнения строковые.
- Демо-данные старше 48 ч пересоздаются сами при запросе `/demo/clients`.
- Тесты ставят `CA_DEMO_HISTORY=0` и `CA_ANALYST_PIN=4321`.
- Файлы в репозитории с окончаниями строк CRLF: правки сохранять так же. `sed -i` в Git Bash превращает CRLF в LF — править через Edit или Python.
- Отказ, после которого нужна запись в журнале, возвращать `JSONResponse(...)`, а не `HTTPException`: исключение откатывает всю транзакцию запроса.
