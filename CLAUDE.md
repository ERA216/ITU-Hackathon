## Идея в одном абзаце

Защищаем честных клиентов от статуса дроппера. Если клиенту пришли чужие деньги, приложение сразу предупреждает и даёт вернуть их отправителю одной кнопкой. Если мошенник уговаривает переслать деньги дальше («ошибочный перевод»), перевод останавливается. Если пострадавший жалуется, система идёт по цепочке переводов: у похожего на невольного участника замораживает только спорную сумму, остальные счета приостанавливает; пострадавший видит статус жалобы и получает замороженные деньги назад. Невольный участник подаёт апелляцию прямо в приложении, со сроком ответа. Втянутый в схему (обычно студент) может сам сообщить банку «Меня втянули» и получить подтверждение с датой. Сотрудник банка видит цепочку, подсказку «невольный участник или организатор» и принимает решение. Вокруг этого: списки Антифрод-центра, сигнал оператора о звонке, доверенное лицо, предупреждение о вербовке, справка о снятии ограничений, проверка подозрительного сообщения, период охлаждения, «встречный кредит» (деньги свежего кредита уходят новому получателю, кредит можно вернуть одной кнопкой), «аренда ИП» (счёт предпринимателя работает как транзит для денег обманутых людей: остановка перевода, вкладка «Аренда ИП» у сотрудника), «перевод под диктовку» (отметки приложения: разговор, вставка из буфера, ссылка из мессенджера, новое устройство), жалоба через другой банк (запрос на заморозку через Антифрод-центр и автоматический ответ на запросы других банков, вкладка «Другие банки»), граф денег в карточке случая, «Сейф» (часть денег под замком: открыть через сутки или в отделении), «касса онлайн-казино» (карта частного лица принимает ставки и платит выигрыши), дроп-фермы и сети дропперов (один телефон — счета многих людей; вкладка «Сети» с графом и приостановкой), «Счёт открыли без меня» (счёт на имя клиента, открытый по дипфейку, клиент закрывает кнопкой «Это не я»), снятие наличных по QR-коду банкомата (деньги незнакомцев за 5 суток — только по лицу, крупное снятие во время звонка — через час), проверка QR-кода перед оплатой, тренажёр против мошенников, правило двух ключей и скрытые персональные данные в панели сотрудника, журнал действий, который нельзя подделать, панель эффективности с показателем «Не пришлось возмещать». Стартовая страница с туром «Показ за 3 минуты».

## Оформление (согласовано с пользователем)

- Стиль по образцу приложения bcc.kz: белый фон страниц, белые карточки с тонкой рамкой `#d6eadf`, скругление 16 px, шрифт Roboto Flex (без загрузки из интернета).
- Акцент — фирменный зелёный `#00ab75` (текст на белом — `#00875c`). Серый пользователю не нравится: вместо серых оттенков мягкие зелёные (`#e6f3ed` заливка, `#587366` подписи).
- Верхнее меню на всех четырёх страницах (экран клиента, панель аналитика, эффективность, качество движка) слева после «Чистый счёт»: выбранный пункт залит зелёным с белым текстом, остальные — чёрный текст без рамок. Так же вкладки «Ждут решения / Все / Связанные счета». «Начать заново» и «Выйти» — белые с зелёной рамкой.
- Экран клиента — телефон с вкладками «Главная / Переводы / Защита». Слева демо-панель: выбор персонажа и подсказка залиты зелёным с белым текстом, кнопка «Включить звонок» красная, примеры сообщений жёлтые. На узком экране демо-панель сворачивается в кнопку.
- Без градиентов, теней-эффектов и эмодзи: проект не должен выглядеть сгенерированным.

## Команды

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload          # http://127.0.0.1:8000/ (стартовая), /client (клиент), /analyst (код 2026), /analyst/stats, /quality
python -m pytest -q                    # 171 тест, ~110–140 с; каждый тест на своей копии базы (на Windows 1 пропускается)
python -m app.quality                  # пересчитать app/static/quality.json (10 наборов + ИП, казино, устройства; ~6–8 минут)
```

Первый запуск сервера ~10 с: создаются демо-данные и история за 30 дней (`CA_DEMO_HISTORY=1`).

Переменные окружения: `CA_DB`, `CA_UPLOADS`, `CA_DOC_KEY` / `CA_DOC_KEY_FILE`, `CA_ANALYST_PIN` (по умолчанию 2026), `CA_DEMO_HISTORY` (1/0), `CA_TZ` (Asia/Almaty), `CA_COOLING_MINUTES` (60), `CA_PUBLIC=1` (хостинг: без PIN код случайный), `CA_HTTPS=1` (secure-куки), `PORT`.

## Устройство

- `app/main.py` — весь API (FastAPI). Один запрос = одна транзакция (зависимость `tx()` с замком; в ней же `_settle_due()` проводит переводы, у которых закончился период охлаждения).
- `app/engine.py` — правила перехвата. Каждый признак = баллы + текст причины. Порог 85, если на счёте есть «чужие» деньги; 60 без них (звонок, серый список, опасное сообщение, деньги свежего кредита). Окно 120 ч, для кредита 72 ч (`fresh_loan`). Также `assess_role` (подсказка сотруднику), `recruitment_signal`, `find_forward`.
- `app/messages.py` — распознавание схем в тексте сообщения (правила ru+kk): mistaken, safe_account, investment, job, fake_letter, fake_alert, fake_invoice. Новые схемы ставить после прежних (при равных баллах побеждает прежняя).
- Клиенты бывают `kind='person'` и `kind='ip'` (ИП, `activity` — вид деятельности). Для ИП не работают признаки «ошибочного перевода», предупреждение «возможно, чужие деньги» и вербовка: вместо них `engine.rental_signal` («аренда ИП») и признак `ip_rental` (60 баллов).
- `app/seed.py` — синтетика (300 клиентов, 90 дней; плюс отдельные подграфы со своими генераторами случайных чисел — на прежние цифры качества не влияют, демо-серверу не нужны, `with_business=False`: ИП `generate_business`, касса казино `generate_casino` с номерами от 5001, устройства `synthetic_devices` с номерами от 9001) и демо-персонажи 1001–1023 (диапазон персонажей 1001–1999; 1023 — второй счёт Венеры, не персонаж). `app/history.py` — смоделированная история случаев за 30 дней (и модель «серого» списка для синтетических дропперов).
- `app/metrics.py` — панель эффективности (в т. ч. `_compensation` — «Не пришлось возмещать», `_loans`) и связанные счета. `app/quality.py` — качество движка.
- `app/i18n.py` — тексты сервера ru/kk (`t(key)`), казахские имена персонажей, причины по коду.
- `app/db.py` — схема SQLite; `SCHEMA_VERSION` (сейчас 15): старая база удаляется и создаётся заново.
- Страницы: `/` — `landing.html` (стартовая), `/client` — `index.html` (экран клиента), `/analyst`, `/analyst/stats`, `/quality`. `tour.js` («Показ за 3 минуты») подключён на стартовой, клиенте, панели и эффективности; шаги — массив `STEPS`, шаг хранится в `sessionStorage` (`ca_tour`); в панели `showPanel()` вызывает `tourResume()`.
- Журнал действий: `app/journal.py` — `seal()` (отпечаток новых записей, вызывается из `log()` и в конце `seed.populate`), `verify()`. Любую новую прямую вставку в `events` тоже запечатывать. Проверка — `/analyst/journal`, демо-подделка — `/demo/journal/tamper`, блок внизу `stats.html`.
- Сотрудники: `EMPLOYEES` в `main.py` (Аружан С., Медет К.), выбираются при входе, в демо переключаются `/analyst/employee`. Правило двух ключей — таблица `approvals`, `_ask_second_key`, `/analyst/approvals/{id}/confirm|reject`, `_close_approvals`; действия — `_refund`, `_decide`, `_suspend_network`. Ключ сети — её дроп-телефон (`metrics.networks`), без телефонов — `n<номер>`.

## Как вносить изменения (сложилось за проект)

- Меняешь схему базы → подними `db.SCHEMA_VERSION` и добавь новую таблицу в список очистки в `seed.populate(reset=True)`.
- Деньги двигаются только через `_move`; резерв = переводы со статусом `held` и `pending` и снятия наличных `ready`/`pending` (`_held_sum`) плюс замороженное (`_frozen_sum`); доступно = `_available(cid)`. Возврат пострадавшему — `_refund` (не больше замороженного и недополученного, `_returned_sum`). Каждое действие по случаю — `log(...)`.
- Любой новый текст для клиента — в `i18n.MSG` (сервер) или в `T` в `index.html`, сразу на двух языках. Казахский потом вычитывает носитель.
- На каждую функцию и каждую исправленную ошибку — тест в `tests/test_flow.py` (сначала воспроизвести, потом чинить).

## Подводные камни

- Индекс по `transfers(status)` ломает план запросов и вдвое замедляет движок; для отложенных переводов — частичный индекс `ix_tr_pending`.
- Имена синтетических клиентов («Данияр О.», «Руслан А.») совпадают с персонажами: в тестах и браузерных проверках искать по «Данияр (продаёт», «Руслан (счёту».
- Даты хранятся как наивное местное время Алматы (ISO-строки); сравнения строковые.
- Демо-данные старше 48 ч пересоздаются сами при запросе `/demo/clients`.
- Тесты ставят `CA_DEMO_HISTORY=0` и `CA_ANALYST_PIN=4321`.
- Файлы в репозитории с окончаниями строк CRLF: правки сохранять так же. `sed -i` в Git Bash превращает CRLF в LF — править через Edit или Python.
- Отказ, после которого нужна запись в журнале, возвращать `JSONResponse(...)`, а не `HTTPException`: исключение откатывает всю транзакцию запроса.
- Вход клиента — одна кука на весь браузер. Экран клиента шлёт `X-Client-Id` (в `api()` в `index.html`), `as_client` при несовпадении отвечает 409 с `X-Session-Changed`. Новые запросы экрана клиента делать через `api()`, а не голый `fetch`.
- Просьбы второго ключа должны закрываться, когда действие стало неактуальным: `_close_approvals(...)`. Новое действие под второй ключ — проверки до изменений, иначе закрытие в `approval_confirm` оставит половину изменений.
- Деньги со счёта списывать через `_move` (он же уменьшает сейф до остатка, `_trim_safe`); если баланс меняется напрямую (кредит), вызвать `_trim_safe` самому.
